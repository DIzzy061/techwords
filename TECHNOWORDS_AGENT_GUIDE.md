## 2. Назначение и платформы

Русскоязычное приложение для изучения английских слов и технических фраз из собственной документации. Пользователь загружает личный словарь и учит по одному термину. Тематика может включать электронику, embedded-разработку и дроны; приложение должно принимать и другую лексику.

| Платформа | Ожидаемый результат |
| --- | --- |
| ПК, Windows, Vivaldi | Обычный автономный HTML открывается двойным щелчком. Версия с ИИ запускает HTML через локальный HTTP-сервер. Установка PWA необязательна. |
| Android, Samsung Galaxy A35 5G, Android 16 | Устанавливаемая PWA, обучение без сети после первоначальной подготовки. |
| iPhone 15, iOS 26 | PWA с теми же основными функциями; настоящую совместимость ИИ нужно проверить отдельно. |

Обычное обучение работает без интернета. Первая установка PWA и загрузка весов ИИ требуют сети; после этого нужен фактически проверенный офлайн-запуск. Облачный API, регистрация и API-ключ не являются обязательными частями приложения.

У конечного пользователя не должны требоваться Android Studio, Node.js или Python. Средства сборки устанавливает разработчик в своей среде.

## 3. Словари и импорт

При первом запуске список пользовательских словарей пустой. Можно предложить отдельную кнопку демонстрационного набора с нейтральными примерами. Личный словарь автора не встраивать в общую сборку.

Формат таблицы:

| Колонка | Содержание | Обязательность |
| --- | --- | --- |
| A | Английское слово, термин или фраза | Да |
| B | Русский перевод или несколько переводов | Да |
| C | Транскрипция / IPA | Нет |

Пример файла, а не встроенный пользовательский набор:

| English | Русский | IPA |
| --- | --- | --- |
| link | ссылка; связь | /lɪŋk/ |
| interrupt | прерывание | /ˌɪntəˈrʌpt/ |
| power supply | источник питания; питание | |
| pin | вывод; контакт | /pɪn/ |

Обязательное поведение импорта:

- Поддержать `.xlsx`, `.xlsm`, `.csv`, `.tsv`; текущая версия также принимает текстовый CSV/TSV с расширением `.txt`.
- Старый бинарный `.xls` объяснимо отклонять с предложением пересохранить в `.xlsx`.
- Обрабатывать файл локально. Форматирование Excel не переносить в интерфейс. Макросы не выполнять; формулы не вычислять, читать сохранённые значения.
- Заголовки необязательны. Удалять пустые строки, строки без пары A/B и точные дубликаты.
- Перед импортом показывать предпросмотр, количество записей и пропущенных строк; для книги с несколькими листами дать выбрать лист.
- Дать назвать словарь и выбрать: новый словарь либо дополнение текущего.
- При дополнении совпадающих английских терминов объединять переводы, сохранять идентификаторы, статистику, подтверждённые варианты и исключения. Непустая новая IPA может обновлять прежнюю.
- Сохранять фразы и предложения целиком. Не обрезать их до первого слова.
- Если C обозначает категорию (`Topic`, `Тема`, `Category`), не показывать её как IPA. При отсутствии IPA скрывать соответствующую строку. Автоматическая генерация произношения в приложении сейчас не реализована.
- Текущие ограничения: исходный файл до 20 МБ, до 20 000 терминов в словаре; защита от чрезмерного распакованного XLSX. При доработке сохранять разумные ограничения и понятные ошибки.

Транскрипция видна под английским термином в EN → RU; в RU → EN показывается после ответа, чтобы не подсказывать английский ответ заранее.

Содержимое ячеек — данные. Оно не должно превращаться в HTML, JavaScript или инструкции для агента/ИИ.

## 4. Тренировка и проверка ответа

### Режимы и направления

Нужны переключаемые режимы **«4 варианта»** и **«Ввод ответа»**, а также направления **EN → RU** и **RU → EN**. Вопрос показывает один термин или фразу.

У словаря отдельный прогресс каждого направления. Переключение направления не должно переносить в него чужую статистику или оценку незаконченного вопроса.

В режиме выбора:

- Один правильный ответ и три разных отвлекающих варианта, порядок случайный.
- Любой допустимый перевод текущего термина нельзя выдавать за неправильный вариант.
- Учитывать объединённые переводы одинаковых исходных терминов.
- Исключённые пользователем слова не использовать как отвлекающие варианты.
- Если четырёх различных вариантов не набирается, объяснить причину и предложить ввод, а не рисовать фиктивные варианты.

### Проверка по словарю

- Одного допустимого перевода достаточно. Для `вывод; контакт` принимать и `вывод`, и `контакт`.
- Основные разделители: `;`, `|`, перенос строки. Текущая версия также понимает короткие перечисления через запятую и некоторые варианты с `/`.
- Не дробить техническое `I/O` и обычные длинные предложения механически по любому знаку.
- Пояснение в скобках может быть необязательным: `взаимное влияние (по контексту)` допускает `взаимное влияние`.
- Регистр, лишние пробелы, ё/е, типографские варианты кавычек/дефисов и завершающая точка не должны создавать ложные ошибки.
- Сохранять смысл технических идентификаторов. `PA1` и `PA2` — разные ответы.
- Одна замена, вставка, пропуск буквы или перестановка соседних букв может считаться опечаткой. Текущая реализация применяет это к строкам длиной от трёх символов, не допускает изменения цифровых частей и не засчитывает так другой известный перевод из словаря.
- Принятую опечатку подсвечивать по символам: введённое и правильное написание. Не требовать набрать все переводы из Excel целиком.

### Последовательность оценки

1. Проверить точное совпадение с вариантами словаря и подтверждёнными пользователем синонимами.
2. Проверить разрешённую опечатку.
3. Для неизвестного ввода в версии с ИИ использовать отдельный процесс оценки из раздела 8.
4. Записывать результат в статистику ровно один раз после окончательного решения.

Кнопка **«Не знаю»** означает пропуск с ошибкой и повторением. Пустой случайный submit не должен создавать несколько ответов.

### Автопереход

После правильного ответа без опечатки следующий вопрос открывается примерно через **1,5 секунды**. Одновременно доступна ручная кнопка **«Следующий»**. Нужны пауза текущего автоперехода и постоянное отключение настройкой.

После ошибки или опечатки не переключать вопрос автоматически: дать прочитать объяснение. Отменять старый таймер при навигации, открытии диалога, смене направления/режима/словаря, скрытии страницы и ручном переходе. Двойной клик или Enter не должны перескочить два вопроса.

## 5. Повторение, статистика и сложные слова

### Повторение ошибок

Ошибка и принятая опечатка возвращают термин через **20–30 других отвеченных вопросов** в том же направлении. Это счётчик ответов, а не минут или дней.

Пока термин ждёт срока, он не должен появляться раньше через обычную случайную выборку. Дубликат того же исходного термина тоже не должен обходить ожидание. Наступившие повторения имеют приоритет перед обычной выборкой. Очередь и текущий вопрос сохраняются.

Если словарь слишком мал и других слов не осталось, показать понятное состояние с предложением добавить слова или явно повторить раньше. Не нарушать интервал незаметно и не зависать.

### Два разных счётчика

- **Слова с верным ответом:** число разных активных слов, для которых был хотя бы один принятый ответ в данном направлении. Увеличивается уже после первого успеха.
- **Закреплено:** три принятых правильных ответа подряд без опечатки. Ошибка и опечатка сбрасывают серию. Один правильный ответ после ошибки даёт только `1/3`.

Принятая опечатка увеличивает общую точность, но требует повторения написания и не закрепляет слово. Подтверждённый человеком перевод по смыслу считается правильным без опечатки. История прежних успехов не исчезает после новой ошибки.

Показывать также число отвеченных вопросов, точность и очередь повторений. Счётчики слов относятся к изучаемым словам; общая история ответов сохраняется после исключения слова.

### Раздел «Сложные»

Собирать слова с ошибками и опечатками, сортировать сначала по числу ошибок, затем опечаток. Дать поиск и фильтры **«Нужно закрепить»**, **«Все с ошибками»**, **«Уже закреплены»**.

Можно тренировать весь отфильтрованный список или одно слово. В отдельной тренировке сложные слова повторяются до трёх правильных подряд, без ожидания 20–30 вопросов. Результаты попадают в общий прогресс; обычный вопрос не перезаписывается вопросом отдельной сессии. После закрепления история ошибок остаётся доступной. Отдельная тренировочная сессия может завершаться при перезагрузке страницы.

## 6. «Уже знаю» и интерфейс

Кнопка **«Уже знаю — не спрашивать это слово»** доступна у вопроса. В словаре есть исключение и возврат.

- Исключать термин из вопросов и повторений обоих направлений, из отвлекающих вариантов и списка тренируемых сложных слов.
- Для одинакового английского исходного термина исключать и его дубликаты.
- Сохранять саму запись, переводы, IPA и историю. Это исключение из обучения, а не удаление строки.
- В словаре нужны фильтры **«Все слова»**, **«Изучаю»**, **«Уже знаю · не спрашивать»** и кнопка **«Вернуть в тренировку»**.
- Если исключено всё, дать перейти в словарь и вернуть слова. Страница не должна становиться тупиком.
- Исключение во время проверки ИИ отменяет устаревший результат и не записывает ответ за исключённое слово.

Пожелание пользователя: **оформлять «Уже знаю» в том же стиле, что обычные кнопки «Ввод ответа» / «Добавить слова»**, с согласованными шрифтом, отступами, скруглением и состояниями нажатия. Не делать основной способ исключения малозаметной текстовой ссылкой.

Основные разделы: **Главная**, **Тренировка**, **Словарь**, **Сложные**. Главная и логотип доступны после загрузки слов; на главной есть продолжение тренировки.

Ориентир текущего оформления: светлый фон `#f5f6f0`, белые карточки, тёмный текст `#202c28`, акцент `#d7ef71`, крупное изучаемое слово, мягкие скругления. На десктопе статистика справа от вопроса, на мобильном — ниже. Интерфейс на русском, английские слова и IPA размечены соответствующим языком.

Проверять ширины 320, 390, 840 и 1280 px, длинные фразы, доступность клавиатурой и читаемость кнопок. Основные ассеты и стили доступны офлайн; внешние шрифты/CDN не обязательны.

## 7. Сохранение и совместимость данных

В существующем приложении ключ localStorage — **`technowords.offline.v1`**, схема — **`schema: 1`**. При доработке не менять ключ и формат без миграции. Сохранять состояние после окончательных ответов и значимых изменений.

Основная структура:

```text
state
  schema, savedAt, activeId
  settings: mode, direction, autoAdvance
  decks[]
    id, name
    words[]
      id, en, ru, ipa?
      excluded?
      aliases?: { "en-ru": [...], "ru-en": [...] }
    progress
      "en-ru" / "ru-en"
        answered, correct
        seen: { wordId: { asked, correct, streak, mistakes, typos? } }
        reviews[]: { wordId, due, gap }
        bag[], lastId
        question?: { wordId, repeat, options[], outcome }
```

`outcome.kind` принимает `exact`, `typo`, `wrong`, `semantic`; также хранятся `correct`, `answer`, `expected`, `gap`. `semantic` означает принятый человеком перевод по смыслу. Разовые асинхронные запросы ИИ и GPU-объекты не сериализуются.

Пример отдельного слова для понимания формата — **не начальный пользовательский словарь**:

```json
{
  "id": "word-example",
  "en": "link",
  "ru": "ссылка",
  "ipa": "/lɪŋk/",
  "excluded": false,
  "aliases": { "en-ru": ["связь"] }
}
```

Чистый старт использует `decks: []`. `aliases` хранит только варианты, которые человек явно сохранил. Исходные поля `en`/`ru` не подменяются рекомендациями модели.

Необходимые операции переноса:

- JSON-копия всех словарей, статистики, очередей, настроек, aliases и исключений.
- Восстановление JSON с валидацией и явным подтверждением замены текущих данных.
- Экспорт самостоятельного HTML с пользовательскими словами и прогрессом. Он должен открываться без соседних файлов; из него удаляются подключения PWA/ИИ. Веса модели в такой экспорт не включаются.
- CSV с английским, русским и IPA; подтверждённые альтернативы включаются в текст переводов. CSV не заменяет полную резервную копию прогресса и исключений.

Обрабатывать недоступность localStorage и переполнение хранилища: показать сообщение и предложить скачать копию. Не молча сбрасывать повреждённый прогресс.

**`file://`, `http://localhost:8787` и HTTPS-сайт имеют разные браузерные хранилища.** Старт с пустым словарём после перехода на другой адрес может быть нормальным. Переносить через JSON из прежней страницы. Автоматической синхронизации между устройствами сейчас нет.

## 8. Локальный ИИ: назначение и обязательное поведение

ИИ нужен для допустимых переводов, которых нет в Excel. Например, при единственном `link → ссылка` пользователь может предложить `связь`. Для отдельного слова учитывать общепринятые значения; для фразы — её полный смысл и контекст. Не требовать единственного буквального совпадения с Excel.

### Что используется сейчас

- WebLLM **0.2.86**, сборщик esbuild **0.28.2**, версии закреплены lockfile.
- Worker с WebGPU, локальные JS-bundle, без обязательного облачного inference.
- **Qwen2.5-1.5B-Instruct** в фактически поддерживаемом MLC-варианте: `q4f16_1` при `shader-f16`, иначе `q4f32_1`. Полный ID и WASM брать из `prebuiltAppConfig` установленного пакета.
- Контекст 2048; генерация текущего вердикта: temperature 0, seed 7, максимум 40 токенов.
- Qwen 0.5B отключена для новой загрузки по результатам качества. Старый пункт появляется только при наличии кеша, чтобы его можно было удалить. Внутренние индексы текущей реализации: 0 — старая 0.5B, 1 — используемая 1.5B.

Это состояние конкретного проекта. Если другой агент меняет модель или библиотеку, он должен проверить совместимость, размер и качество заново, а не просто подставить похожий ID.

### Подключение и состояние

CMD запускает страницу, но **сам не включает модель**. Пользователь нажимает **«Подключить ИИ» → «Загрузить / открыть модель»**. Первая загрузка требует сети. После перезапуска страницу нужно снова подготовить к работе с моделью; уже сохранённые файлы берутся из кеша.

Показать понятные состояния: выключен, загрузка/подготовка, готов, проверка, ошибка. Рядом с вводом обязательно виден текущий источник проверки: **«Проверка по словарю · ИИ не подключён»** либо **«Словарь + ИИ»**. Настройки доступны оттуда же.

Панель содержит диагностику WebGPU, прогресс, остановку, включение проверки и удаление выбранной модели. Перед состоянием ready выполнить подготовительную генерацию, чтобы первая компиляция GPU не задержала первый настоящий ответ без объяснения.

Текущие таймауты: загрузка до 20 минут, подготовка до 180 секунд, обычная проверка до 45 секунд. Пользователь может остановить процесс раньше. При ошибке GPU/сети обычное обучение остаётся доступным; частичный кеш можно использовать при повторе.

### Контракт проверки

```text
Вход:
  prompt             — показанное слово/фраза
  translations[]     — примеры из словаря и сохранённые варианты
  direction          — en-ru или ru-en
  answer             — введённый ответ

Выход модели:
  { "verdict": "correct" | "incorrect" | "unsure" }
```

Ограничивать вход, проверять JSON и завершённость ответа. Текущие лимиты: термин и ответ до 500 символов, до 12 примеров переводов. Текст словаря передавать как данные, а не системные инструкции.

**Любая новая рекомендация ИИ требует решения человека, включая `correct`.** Маленькие модели ошибались даже в очевидных технических противоположностях и следовали инструкции, введённой вместо перевода.

Пока оценка не подтверждена:

- Не увеличивать количество ответов, правильных ответов и ошибок; не менять очередь и серию закрепления.
- Не запускать автопереход, не принимать повторный submit.
- Предложить подтвердить разово, сохранить свой перевод, явно засчитать ошибку либо изменить ответ.
- При отсутствии/неготовности ИИ в версии с ИИ неизвестный перевод тоже остаётся без оценки: предложить открыть модель или выбрать оценку самому. Это исправление сделано после жалобы пользователя на молчаливую проверку только по Excel.
- В обычном автономном HTML без ИИ сохраняется обычная проверка по словарю.

После явного сохранения вариант становится допустимым для соответствующего направления и принимается дальше без ИИ. Дать удалить его из словаря.

Свободные объяснения модели оказались ненадёжными. Сейчас интерфейс показывает фиксированный понятный текст и реальные варианты из словаря, а не выдуманные причины отказа.

### Асинхронность

Проверка должна быть привязана к конкретному словарю, направлению, вопросу и сессии. При уходе со страницы, смене режима/направления/словаря, исключении слова или отмене поздний результат игнорируется. Остановка worker и таймаут не должны очищать обработчик отмены уже нового запроса или записывать результат за другой вопрос.

### Что действительно проверено

На Windows, Vivaldi, аппаратном Intel Gen12LP, `shader-f16`:

- Настоящая 1.5B загружалась и генерировала ответы.
- После полного закрытия и нового запуска браузера уже без сети модель открылась из кеша и выдала ответ.
- Проверены реальный ввод, подтверждение, сохранение нового варианта, следующий ответ без вызова модели, отмена генерации и удаление выбранного кеша с сохранением словаря и другой модели.
- В небольшом наборе из 15 случаев 1.5B дала 13 ожидаемых вердиктов и два ложных принятия. Это не универсальная оценка точности.
- В финальном коротком формате 0.5B ответила `unsure` на все 15 случаев и не используется для нового подключения.

Скорость 1.5B после подготовки на этом ПК была примерно 3,5 секунды на проверку. Переносить это число на телефоны нельзя. Физические Samsung/iPhone, GPU OOM/device loss и удаление кеша операционной системой ещё не проверены.

## 9. Упаковка, PWA и обновления

### Обычный HTML

Один `TechnoWords.html` с локально встроенными CSS, логикой, импортом XLSX и лицензиями. Открывается как файл, без обязательного сервера и внешних загрузок. Не добавлять в него обязательную зависимость от облака или соседнего JS.

### ПК с ИИ

Папка `dist-desktop/` содержит HTML, JS-bundle/worker, панель ИИ, лицензии, инструкцию, `Start-TechnoWords.cmd` и `Start-TechnoWords.ps1`.

Текущий запуск использует встроенный PowerShell Windows и TCP-сервер только на loopback, постоянный адрес **`http://localhost:8787/`**, разрешённый список файлов. Он не должен раздавать произвольные файлы диска или требовать права администратора. Пользователь держит окно запуска открытым.

Сохранять адрес и порт: произвольная смена origin создаст впечатление потери прогресса. Открывать в браузере пользователя, в данном случае Vivaldi.

### PWA

`dist-pwa/`: `index.html`, manifest, service worker, локальные JS, иконки 192/512, Apple touch icon, лицензии и `.nojekyll` для GitHub Pages. Для установки на телефоне нужен HTTPS. На localhost можно разрабатывать и тестировать.

Поддержать размещение в подпапке `/repo/`: относительные пути, согласованные scope/start_url/id. Оболочка офлайн и модельный кеш — отдельные механизмы.

Обновления:

- Новую оболочку скачивать целиком до признания её установленной.
- При открытии/возвращении сети проверять обновление и показывать **«Применить обновление»**.
- Не перезапускать текущую тренировку неожиданно.
- Удалять только старые собственные кеши оболочки `technowords-shell-*`.
- Сохранять localStorage, IndexedDB и модельные кеши.
- Веса модели не обновлять автоматически вместе с интерфейсом.

CSP текущей версии разрешает локальные скрипты/worker, `wasm-unsafe-eval` и нужные соединения к `huggingface.co`, `*.hf.co`, `raw.githubusercontent.com`. Не расширять её до произвольных источников ради обхода ошибки без диагностики. Требование безопасности важно и при новой архитектуре.

Не объявлять модель готовой к офлайн-работе только по `hasModelInCache`: нужно реально отключить сеть, пересоздать браузер/worker и выполнить inference. Наличие WebGPU в отчёте устройства тоже не гарантирует запуск конкретной модели.

## 11. Сборка и проверка

Среде разработчика нужны подходящий Node.js, менеджер пакетов, JSZip/Pako и Playwright для браузерных проверок. В существующих скриптах часть путей указывает на bundled runtime конкретной машины; на другой машине адаптировать разрешение зависимостей. В `build.mjs` путь к JSZip/Pako настраивается переменной `TRAINER_NODE_MODULES`.

Последовательность сборки существующего проекта из корня:

```text
cd ai-engine
pnpm install --frozen-lockfile
cd ..
node ai-engine/build.mjs
node build.mjs
node build-pwa.mjs
node build-desktop.mjs
```

Если обычный тренажёр не менялся, не нужно пересобирать или повторно тестировать несвязанные части без причины. Собирать архивы только из соответствующего `dist-*`, включая лицензии, а не из всей рабочей папки.

Основные тесты:

```text
node --test tests/core.test.cjs tests/ai-core.test.mjs tests/excluded.test.cjs
node tests/ai-browser.cjs
node tests/pwa.cjs
node tests/learning.cjs
node tests/desktop.cjs
```

Установленный браузер задаётся через `TRAINER_BROWSER_EXECUTABLE`. На исходном ПК это `C:/Users/User/AppData/Local/Vivaldi/Application/vivaldi.exe`; данный путь не является требованием к новой машине.

UI-тесты с подставленным вердиктом проверяют состояние приложения, но не качество или запуск модели. Для настоящего WebLLM используется `tests/ai-real.cjs` с отдельным тестовым профилем и разрешённой аппаратной GPU.

```text
TRAINER_BROWSER_EXECUTABLE=<путь к Vivaldi>
TRAINER_REAL_LOAD=1
TRAINER_REAL_MODEL=1
node tests/ai-real.cjs
```

Это обозначение переменных среды, а не универсальная команда для любого shell. В PowerShell использовать `$env:ИМЯ = 'значение'`.

Дополнительные параметры настоящего теста:

- `TRAINER_REAL_TAG` — суффикс отдельного отчёта.
- `TRAINER_REAL_CASES=0` — пропуск набора из 15 примеров.
- `TRAINER_REAL_LIFECYCLE=1` — полное закрытие и офлайн-перезапуск браузера, затем удаление выбранного **тестового** кеша модели.
- Без `TRAINER_REAL_LOAD=1` — диагностика без скачивания модели.

У текущих headless-тестов Vivaldi есть специальные параметры запуска. Для обычного UI используется `--disable-gpu`; для настоящего inference этот флаг обязательно убрать. Использовать отдельный профиль и закрывать только собственные тестовые процессы. Headless Vivaldi в этом окружении не выдаёт download events: существующие тесты проверяют реальные сформированные Blob.

### Минимальные приёмочные сценарии

| Сценарий | Ожидаемый результат |
| --- | --- |
| Новый запуск | Пустые пользовательские словари, доступен импорт. |

## 12. Что осталось и с чего продолжать

Для существующего проекта основное приложение и ПК-проверка ИИ уже выполнены. Следующему агенту не нужно начинать их заново.

1. **HTTPS и телефоны.** Пользователь сообщил, что отдельного GitHub-репозитория пока нет. Получить ссылку или явное поручение на создание/публикацию, затем разместить подготовленную PWA. Посторонние проекты пользователя не использовать как место публикации по совпадению названия.
2. **Физические устройства.** Проверить Samsung A35 и iPhone 15: установка, импорт, клавиатура, полный офлайн-перезапуск, WebGPU worker, память и кеш. В прежних скриншотах WebGPU был доступен, но это не проверка inference. Память RAM Plus не считать физической ОЗУ.
3. **Качество ИИ.** Расширить независимые тесты технических противоположностей, новых значений, чисел, идентификаторов и инструкций в данных. Изучать более подходящие небольшие модели при необходимости. Не возвращать автоматический positive по результату пары удачных примеров.
4. **Отказы.** Проверить и обработать нехватку GPU-памяти, потерю устройства и удаление кеша системой. Не провоцировать опасные эксперименты с памятью на пользовательской машине; отделять симуляцию отказа от настоящего аппаратного теста.
5. **Переносимость разработки.** Убрать привязку тестов к путям одной машины через конфигурацию зависимостей, сохраняя доступный пользователю запуск без инструментов разработки.

После изменений обновлять `CONTINUE.md`, результаты проверок и этот документ, если изменились требования или архитектура. Сохранять рабочую предыдущую версию перед заменой пользовательского HTML.
